Protecting SaaS Data: Risks & Controls

Module 12 Data risks DLP · CASB
In this note
  • The other half of SaaS security (after identity): the data
  • The three security risks to SaaS data — and how each is stopped
  • DLP inspects content; CASB polices movement; sharing controls tighten access
  • The toolkit, and where these controls sit in today’s market

1 Security risks to SaaS data

Once your data lives in someone else’s cloud, you can’t wrap a firewall around it. Three risks dominate — expand each to see how it happens and how it’s stopped:

A valid user drops regulated data somewhere it isn’t allowed — credit-card numbers in a public bucket, patient records in an unencrypted folder. The data may be perfectly accessible; it just shouldn’t live there, and a regulator (PCI, HIPAA) will fine you. Identity can’t catch this — it checks who logged in, not what they uploaded. The fix reads the content itself:

DLP · content inspection

Tool · DLP (Data Loss Prevention)
DLP engines read file content for patterns — credit cards (PCI), SSNs (PII), medical records (HIPAA), or keywords like “Confidential.” On a hit they quarantine, redact, or alert. Examples: AWS Macie (classifies data in S3), Box Shield (a SaaS app).

The data didn’t move — the access did. The classic case: a file shared as “anyone with the link can view,” so contractors, ex-employees, even search engines can reach it. The fix is to tighten how broadly things are shared:

Who can open this file?

Tool · sharing controls
Tighten sharing defaults, expire links, and restrict each file or folder to named people instead of “anyone with the link.” Regular access reviews catch over-shared data and over-privileged guests before they’re exploited.

Even data that’s safe inside corporate Box must not escape — downloaded to a personal laptop, or synced to a personal Google Drive. Once it’s out of the corporate cloud, you’ve lost all control. A policy “traffic cop” sits between users and the app and stops the escape:

CASB · stopping exfiltration

Tool · CASB (Cloud Access Security Broker)
A CASB enforces guardrails around the data: device control (block downloads to unmanaged devices) and cloud-to-cloud control (spot an unauthorized connection and revoke the OAuth token, breaking the sync).

2 The toolkit

Each risk maps to a control and a class of tool. Together with identity, they replace the firewall you no longer control:

RiskThe questionControlExample tools
Compliance violationAllowed to exist here?DLP — content inspectionAWS Macie, Box Shield
Unauthorized accessShared too widely?Sharing controls + access reviewsBuilt-in sharing settings
Data exfiltrationAllowed to leave here?CASB — movement controlCASB / SSE platforms
How these fit together
Identity (OIDC + MFA) gates who gets in; these controls protect the data once they’re in. In practice the lines blur: DLP usually runs inside a CASB, and CASB itself now ships as part of a broader cloud-security platform — SSE (Security Service Edge) / SASE (Secure Access Service Edge) — alongside a secure web gateway and ZTNA (Zero Trust Network Access). The concepts stay the same — the product names consolidate.
Where encryption fits
In SaaS the vendor encrypts your data at rest and in transit by default — that job moved to them in the pivot. Your remaining lever is bring-your-own-key (BYOK): supply your own keys (Module 9) so you control access and can revoke them to make the data unreadable — even to the vendor. Some CASBs go further and tokenize sensitive fields before they ever reach the app.
Remember

Three security risks to SaaS data — each with a control:

  • ◇ Compliance violation (data where it shouldn’t be) → DLP inspects content for PCI/PII/HIPAA — quarantine / redact / alert
  • ◇ Unauthorized access (loose sharing / public links) → sharing controls + access reviews
  • ◇ Data exfiltration (to unmanaged device / cloud) → CASB blocks downloads and revokes cloud-to-cloud OAuth tokens

Identity gates who gets in; encryption/BYOK keeps data confidential. DLP often lives inside a CASB, now usually part of an SSE/SASE platform.
