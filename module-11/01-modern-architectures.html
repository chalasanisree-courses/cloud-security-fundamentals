1 Two layers, two evolutions

2 Infrastructure layer — how we run code

The bottom layer kept handing more of the stack to the cloud vendor. Each step packs apps tighter and leaves you managing less. Step through them — the shipping analogy rides along:

Physical → VM → container → serverless

Why containers exist
Two apps that need different library versions (Python 3.12 vs 3.14) used to need separate machines — “dependency hell.” A container packages an app with its own libraries, so many isolated apps share one machine. That solves both the dependency clash and the waste of a whole OS per app. Kubernetes is the software that runs and scales fleets of containers across many machines.

4 Putting it together: microservices on serverless

Modern apps sit at the intersection of both axes: a microservices app (application layer) where each service scales on its own, all running on serverless infrastructure (infrastructure layer) the vendor manages. Add instances and watch each service scale independently:

Microservices behind an API Gateway, scaling on a serverless platform

The front-door swap
A load balancer spreads requests across a fixed pool of servers. In serverless there are no servers to balance, so an API Gateway takes the front-door role — it validates each request and routes it to the right service (triggering a Lambda function, or reaching a Fargate container). Same job, no servers underneath.

5 Does the security still apply?

The application-security defenses shift when the architecture moves from a traditional 3-tier app to the modern principles above — some carry over, some change where they live and who owns them. Click a control to see what happens to it:

Securing the app, in containers & serverless

The pattern
As you move VM → container → serverless, shared responsibility slides toward the vendor for the infrastructure and toward you for code, identity, and data. Same defense-in-depth — repositioned, with a bigger internal attack surface (many services, many APIs) to watch.
Remember

Two evolutions, one app:

  • ◇ How code is structured — monolith → microservices
  • ◇ How code runs — hardware → VM → container → serverless

Put together: microservices on containers or serverless, behind an API Gateway.

Security repositions (it doesn’t disappear):

  • ◇ WAF & Shield move to the API Gateway
  • ◇ Host duties shrink toward least-privilege functions
  • ◇ Microservices add an internal attack surface
