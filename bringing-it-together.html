Course Wrap-Up · Security & the Cloud

Past, Present & Future

One trend has reshaped security more than any other: cloud migration. It moved the users and the data out of the building — and forced security to change with them. Here is the arc: where we were, why we moved, where we are, and where we’re going.

Past

The castle and the moat

For decades, we secured a company like a medieval castle: build one strong perimeter, put everyone and everything inside it, and treat inside as trusted and outside as dangerous.

It worked because it matched reality. Employees sat at desks inside the office. The applications and data lived on servers inside the data center. So a firewall at the gate — deciding who crosses the moat — really did protect almost everything that mattered.

That castle is most of what this course covered. On a foundation of how the internet works and how a single connection is secured — TCP/IP, cryptography, TLS, and the CIA triad — we stacked the layers of defense: network, device, identity, application, and data, wrapped with cross-cutting key management and logging. The chapters that follow are how that whole picture is now changing.

The assumption
Trust is based on location. If you’re inside the network, you’re trusted; if you’re outside, you’re not. The whole model rests on that one idea.
Why we moved

Cloud migration broke the perimeter

Then the cloud changed where everything lives. Toggle before and after:

The wall now surrounds nothing
The users left the building (working from home, from a cafe) and the data left the building (apps now live in SaaS and public clouds like AWS). Once the people and the data are outside the wall, “inside vs outside” no longer means “safe vs dangerous.” The perimeter still exists — it just doesn’t contain what we care about anymore.
Present

Zero Trust — never trust, always verify

If location can no longer earn trust, then nothing should be trusted by default. That is Zero Trust: every request must prove itself, every time — no matter where it comes from. Watch the same request hit each model:

What Zero Trust actually means
No implicit trust from being “on the network.” Every request re-verifies identity (who), device (is it healthy), and context (is this normal), and is granted only least privilege — the minimum needed, for this action, right now. In short: identity becomes the new perimeter.

The whole trend in one line

Security used to trust a place (inside the castle). Cloud migration moved the people and the data out of that place, so security shifted to trusting a verified identity instead (Zero Trust). What’s next — AI on both sides, passwordless identity, and quantum-safe cryptography — all push the same idea further: verify everything, trust nothing by default.
