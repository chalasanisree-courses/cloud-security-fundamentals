2 The cloud is a landlord

One cloud hosts thousands of tenants. Each gets a private, walled-off space — on AWS, a VPC (Virtual Private Cloud). Click a tenant to see what they can and can't reach:

Why the VPC matters for security
The VPC is the cloud's isolation boundary — logical separation between you and every other tenant on the same shared hardware. It's also the network layer of defense in depth, and the whole subject of the next module.

3 Where the cloud lives: regions & zones

The landlord doesn't own one building — it owns clusters of data centers all over the world. Two words describe that geography, and together they're what make the cloud resilient.

A region is a geographic cluster of data centers in one part of the world — N. Virginia, Ireland, Mumbai, São Paulo. Each region is fully independent: an outage in one does not affect the others. You choose which region to deploy in, driven by latency (put the app near your users) and data-residency law (EU customer data may be required to stay in the EU).

Inside a region are Availability Zones (AZs) — one or more physically separate data centers, each with its own power, cooling, and networking, linked to the others by fast private fiber. Because the buildings are isolated, a fire, flood, or power failure in one AZ doesn't touch the next. Spreading your app across AZs is how a single building can go dark while your service stays up.

Regions & AZs are shared responsibility
AWS guarantees the infrastructure within each region — the buildings, power, and the isolation between AZs. Whether your application actually survives a failure is your design choice: running across multiple AZs (or regions) is something you architect and pay for, not something you get automatically.

Security cuts both ways
A reviewed, hardened template deploys identically every time — but one bad line (an open security group, a public bucket) is reproduced everywhere. Infrastructure as Code is misconfiguration as code too, so templates get security-reviewed like any other code.

Remember

Traditional infrastructure means siloed teams (storage, systems, network) whose coordination is the bottleneck. The cloud is a multi-tenant landlord giving each tenant an isolated VPC — the network boundary covered next. That hardware lives in independent regions worldwide, each split into isolated Availability Zones; spreading an app across them is how it survives a data-center failure. Old resources map onto services: compute → EC2, networking → VPC subnets/route tables (+ Internet Gateway), storage → S3. You provision by writing code — Infrastructure as Code, reconciled by Terraform — and ship through a continuous DevOps loop.
